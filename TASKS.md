## Загальний опис застосунку

У попередньому домашньому завданні ви побудували REST API з автентифікацією та захистом маршрутів. Цього разу застосунок отримує покращення, необхідні для production середовища.

### Потрібно реалізувати:

1. Базову безпеку — CORS, helmet, rate limiting на auth-маршрути
2. Логування — pino для HTTP-запитів та подій в контролерах
3. Фото оголошення — завантаження через multer та збереження в Cloudinary
4. Тестування — базові тести через Vitest


## Функціональні вимоги

### 1. Базова безпека

Застосунок має бути захищений трьома рівнями безпеки.

**Helmet** встановлює безпечні HTTP-заголовки автоматично. Підключається один раз як middleware в app.ts до всіх маршрутів.

**CORS** налаштовується через пакет `cors` і дозволяє звернення лише з дозволених джерел. Список дозволених origins береться зі змінної оточення `ALLOWED_ORIGINS`.

**Rate limiting** обмежує кількість запитів до auth-маршрутів — не більше 10 запитів з однієї IP-адреси за 15 хвилин. При перевищенні ліміту сервер повертає 429 з повідомленням `"Too many requests, please try again later"`.



### 2. Логування через pino

Логування реалізується через `pino` та `pino-http`. Кожен HTTP-запит логується автоматично через pino-http middleware. Крім того, в контролерах логуються важливі події — реєстрація нового користувача, вхід, створення оголошення, завантаження фото.

Логер ініціалізується один раз в окремому файлі `src/logger.ts` і імпортується звідти в усі місця де потрібен.

### 3. Фото оголошення

Маршрути `POST /announcements` та `PATCH /announcements/:id` отримують можливість приймати фото. Запит надсилається як `multipart/form-data` замість JSON.

Multer зберігає файл тимчасово на диску в директорії `uploads/`. Після збереження файл завантажується на Cloudinary, а локальний файл видаляється.

В базі даних зберігається лише URL фото який повернув Cloudinary. Поле `imageUrl` в моделі `Announcement` є опціональним — оголошення можна створити без фото.

Приклад відповіді при створенні оголошення з фото:
```json
// 201 Created
{
  "id": 1,
  "title": "Продам велосипед",
  "description": "Trek у відмінному стані, розмір рами L, колеса 29 дюймів, гідравлічні гальма",
  "price": 8500,
  "category": "sale",
  "imageUrl": "<https://res.cloudinary.com/demo/image/upload/v1/announcements/abc123.jpg>",
  "createdAt": "2025-03-02T10:00:00.000Z",
  "updatedAt": "2025-03-02T10:00:00.000Z",
  "user": {
    "id": 1,
    "username": "ivan_petrenko",
    "email": "ivan@example.com",
    "name": "Іван"
  }
}
```

### 4. Тестування через Vitest

Застосунок має містити базові тести. Мінімальна вимога — 3 тести що демонструють вміння налаштувати тестовий фреймворк і написати перевірки.

Приклади того, що можна протестувати:

- Unit тест для функції генерації токенів
- Unit тест для хешування паролів
- Integration тест для POST /auth/register — повертає 201 при валідних даних
- Integration тест для POST /auth/login — повертає 401 при невірному паролі
Ви маєте самостійно обрати, що тестувати. Головне — продемонструвати розуміння принципів тестування.

## Технічна реалізація

### Оновлена схема бази даних

Модель `Announcement` розширюється опціональним полем `imageUrl` типу `String`. Після змін запустіть міграцію.

### Нові файли в проєкті

До вже створеної структури директорій проєкту додаються:
```bash
hw/
├── src/
│   ├── middleware/
│   │   └── upload.ts          # новий
│   └── logger.ts              # новий
├── tests/
│   └── auth.test.ts           # новий
├── uploads/                   # нова директорія
└── vitest.config.ts           # новий
```
Решта структури залишається з попереднього завдання.


### Змінні оточення

Додайте до `.env` нові змінні:
```js
CLOUDINARY_CLOUD_NAME=your_cloud_name
CLOUDINARY_API_KEY=your_api_key
CLOUDINARY_API_SECRET=your_api_secret
ALLOWED_ORIGINS=http://localhost:5173,<http://localhost:3000>
```

## Підказки для реалізації

Логер ініціалізується один раз і імпортується звідти де потрібен:
```js
// src/logger.ts
import pino from 'pino'

const logger = pino({
  level: 'info',
  transport: {
    target: 'pino-pretty',
  },
})

export default logger
```
Після завантаження файлу на Cloudinary видаляйте тимчасовий файл з диску через fs.unlink() — не залишайте локальні копії.

Rate limiter підключається лише до auth роутера, а не до всього застосунку. Імпортуйте його в auth.routes.ts і застосуйте до всіх маршрутів цього роутера.

Для Vitest створіть конфігураційний файл в корені проєкту:


Змінні середовища для JWT:
```js
// vitest.config.ts
import { defineConfig } from 'vitest/config'

export default defineConfig({
  test: {
    globals: true,
  },
})
```

Додайте скрипт в `package.json`:
```js
{
  "scripts": {
    "test": "vitest"
  }
}
```
